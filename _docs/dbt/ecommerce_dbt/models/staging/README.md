# staging

> **Directory:** `dbt/ecommerce_dbt/models/staging`

## Purpose

This directory contains dbt staging artifacts that declare the raw Bronze source and implement staging transformations for product data in the ecommerce project. It groups source declarations, model metadata, and two SQL staging models that standardize and expose product attributes for downstream transformations and reporting.

The files include a source declaration pointing to the warehouse Bronze layer, a schema file that documents and tests the canonical staging model, and SQL models that produce both a comprehensive snapshot view and a most-recent-record staging projection of product data.

| `stg_product_snapshots.sql` | This SQL model defines a staging view for product snapshot data by selecting a comprehensive set of product attributes from a Bronze source table named bronze_products and maps several source columns into standardized names. |

## Key Components

- **`Bronze source declaration`** (in `sources.yml`) — It registers the Bronze layer and the bronze_products table in the warehouse so that downstream dbt models in this directory can reference the raw source objects with dbt source macros.
- **`stg_products model documentation and tests`** (in `staging.yml`) — It attaches column-level documentation and data tests to the stg_products staging model, making the intended schema, expected data quality rules, and human-readable descriptions available to developers and CI processes.
- **`product snapshot view`** (in `stg_product_snapshots.sql`) — This SQL model exposes a comprehensive snapshot-shaped view of product attributes from the Bronze source, providing a rich, standardized set of fields for analysis or for other models to consume.
- **`most-recent staging projection`** (in `stg_products.sql`) — This SQL model implements the canonical staging shape by selecting the latest snapshot per product id, producing a cleaned and current product record set intended for downstream transformations and consumption.

## Architecture Notes

The directory is organized around a single Bronze source declaration, a schema file for model documentation/tests, and two SQL staging models that transform Bronze data into usable staging shapes. sources.yml declares the dbt source named "bronze" and the bronze_products table in the warehouse schema; it establishes the raw objects that the SQL models read from. staging.yml provides the schema-level metadata and tests for stg_products rather than implementing transformation logic. The two SQL files implement different staging projections: stg_product_snapshots.sql creates a comprehensive snapshot view by selecting and standardizing many product attributes from the Bronze table, while stg_products.sql focuses on producing the most-recent record per product using a windowed ROW_NUMBER() with QUALIFY and then renaming and selecting the canonical set of fields. Together, these files separate concerns of source registration, model documentation/testing, and staging transformation logic to make the Bronze product data available in both snapshot and current-record forms.
